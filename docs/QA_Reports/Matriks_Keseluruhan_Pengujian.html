Matriks Keseluruhan Pengujian Sistem (QA Architecture)

Aplikasi HYDE - Rangkuman Strategi Quality Assurance (Fungsional, Mutasi, dan Kinerja)

Pengujian pada aplikasi HYDE dirancang menggunakan pendekatan arsitektur QA berlapis (Multi-layered QA Architecture). Matriks di bawah ini memetakan bagaimana ketiga jenis pengujian saling melengkapi satu sama lain untuk memastikan kualitas sistem dari segi logika internal, perilaku pengguna, ketahanan kode terhadap bug, hingga skalabilitas infrastruktur.

Jenis Pengujian Ruang Lingkup & Fokus (Scope) Tools & Metodologi Penjelasan & Tujuan (Objective) Hasil Akhir (Metrik Utama)
1. Pengujian Fungsional
White-box Black-box
  • Whitebox: tests/whitebox/ (Otentikasi, Transisi Status, PDF, QR Logic).
  • Blackbox: tests/blackbox/ (Alur UI/E2E Pengguna, Browser sungguhan).
  • Jest (Whitebox Unit)
  • Playwright (Blackbox E2E)
 Menguji apakah fitur-fitur aplikasi berjalan sesuai spesifikasi (Happy Path & Negative Path). Jest memastikan hitungan logika internal akurat, sedangkan Playwright memastikan antarmuka (UI) dapat dioperasikan oleh pengguna.
  • Seluruh Test Cases berstatus PASS (100%).
  • Fungsi utama (upload, scan QR, validasi) berjalan tanpa kegagalan.
2. Pengujian Mutasi
Mutation Testing 		Fokus Eksklusif: Core Business Logic (lib/*.ts) dan API kritis (blob/proxy/route.ts, transactions/[id]/route.ts, scan/route.ts).
  • StrykerJS
  • Mode: Targeted Full Suite (termasuk mock Prisma).
 Menguji si Penguji (Testing the Tests). Menyusupkan bug buatan (mutant) ke dalam kode sumber untuk mengukur seberapa teliti dan sensitif pengujian White-box dalam menyadari kerusakan tersebut.
  • Mutation Score: 65.91% (Lulus standar industri >60%).
  • Fungsi utilitas (95%-100%), API Scan (82.28%), API Blob Proxy (69.62%).
3. Pengujian Kinerja
Load Testing Stress Testing 		Infrastruktur & API:
Rute GET /api/destinations di lingkungan Local Production (mesin lokal) dan Cloud Production (Vercel Edge & MongoDB Atlas).
  • Grafana k6
  • Matriks Skala: 10, 50, 100, 150 VU.
  • Puncak: 2000 VU.
 Menguji keandalan (reliability) dan skalabilitas peladen (server) saat menerima lonjakan lalu lintas yang masif. Memastikan koneksi database tidak tumbang akibat batas limit koneksi (Connection Pooling).
  • Skala 150 VU: 0% Error, Latensi Vercel P95 ~591ms.
  • Stress Test (2000 VU): Aplikasi tidak mati berkat antrean Event Loop, mengalami Graceful Degradation (latensi memanjang hingga 19 detik namun koneksi DB tetap utuh).
